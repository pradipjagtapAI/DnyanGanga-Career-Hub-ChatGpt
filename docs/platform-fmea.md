# Career platform failure analysis and release gates

Reviewed 12 October 2026. This FMEA describes the current bounded platform. Scores are **engineering prioritization assumptions, not measured incident rates**. Severity (S), occurrence (O) and detection difficulty (D) use 1 (low) to 5 (high); higher D means harder to detect. RPN = S × O × D is a simple triage aid, not a probability, financial loss estimate or security certification. Disabled submission/billing reduces current exposure; assess again before enabling them.

## Evidence and controls classification

Implemented with offline regression coverage: owned selected resumes, global/campaign mandatory intersection, fixed fit/independent priority, claim questions, task leases/idempotency, isolation in stores, current-policy checks, immutable manifest hashing, quota reservations, no automatic unsupported submissions and real local result counts. Tests are authorized local fixtures, not live employer/provider activity.

Implemented but needing hosted/live evidence: D1 conditional transaction behavior under concurrent production requests, real private file/cache delivery, scheduler service access, sender callbacks/unsubscribe, supported provider model behavior and private isolated document processor execution. The final release handover lists the actual commands/results; this table does not invent a penetration-test pass.

Externally required: licensed source permissions; approved AI data policy/model budget; verified sender/domain/templates and opt-ins; independent authentication/MFA review for administrator/sensitive features; HTTPS/hosting protections; retention/privacy review for launch jurisdictions; encrypted backup restore test; measured load and monitoring incident ownership. Latest stable ASVS reviewed is 5.0.0; applicable Level 2 controls are a target and need requirement-level evidence, not a certification. [OWASP ASVS project](https://owasp.org/www-project-application-security-verification-standard/).

Not applicable to enabled code: raw-card processing, refunds, payouts, employer submission and automatic networking messages because these capabilities remain disabled. Their future controls must be implemented/tested before activation rather than marking a disabled placeholder as secure commerce.

## Troubleshooting by mechanism

| Symptom | Check the actual mechanism | Safe repair and verification |
| --- | --- | --- |
| Not Connected / local self-review | Task route, global model allowlist, data approval, key and token/request limits | Configure approved server policy; use authorized staged profile and inspect immutable minimized request/result. Never expose a key in browser settings. |
| No jobs or unknown requirements | Source failure versus no new suitable jobs, rights allowlist, complete snapshot, mandatory missing fields | Import a real description or restore an approved feed; preserve unknowns and explicit filters; do not broaden location silently. |
| Queued tasks after a run | One-call budget, pending board dependencies, category pause, lease and age | Continue once; verify durable completed/queued counts. For uncertain external attempts reconcile before retry, without declaring success. |
| Run stopped as stale | Profile/resume/campaign/vault/answer freshness/settings changed | Review current records and start a new context-bound run. Reusing an old approval is unsafe. |
| No promised next-run time | Schedule disabled, no recent worker health, wrong private service credential | Verify actual Cron request and dedicated authentication; nextRunAt stays null until observed. Do not display a synthetic running service. |
| Accepted but not delivered | Provider callback signature/body, delayed webhook, provider message ID | Preserve accepted status, inspect provider status, retry verified callbacks. A delayed failure must not downgrade delivered. |
| Learning or market count looks small | Up to configured owned eligible jobs; explicit requirements only; duplicate primary selection | Review the real sample/source dates. Increase permitted coverage only after source rights/limits; do not claim market-wide demand. |
| Cost is unknown | Total tokens lack input/output/model invoice and non-AI provider charges | Reconcile recorded usage with operator invoices; monetary null is truthful. Do not convert a quota reservation into a charged transaction. |

## Maintenance and incident procedure

Before any broad launch, name a security contact and an on-call owner; no address is invented in this code. Send operational alerts to that configured private destination for suspicious identity events, authorization violations, signature/callback failures, uncertain sends, missing worker health, source failures, backlog, AI quota anomalies and provider spending. These operator alerts require actual monitoring setup and are not claimed running here.

Review dependency/security notices weekly and apply verified urgent fixes promptly. Re-run affected ownership/context/injection regressions after changes. Review model and source permissions monthly and before adding a board/provider. Reconcile provider invoices and approved spend ceilings daily while enabling live traffic. Review retention and manual CRM consent regularly; minimize private audit data while preserving required traceability.

Take encrypted database/storage backups with separate restricted credentials and a stated retention period. In a private recovery environment, restore the database and private objects, verify counts/hash-linked resume/package lineage/permissions, repeat cross-owner downloads and signed-callback/idempotency checks, and record the actual restore duration. Backups are not verified until this exercise succeeds; this implementation has not performed it.

For an incident: pause affected/global automation and channels; revoke compromised credentials/service access; preserve private evidence without publishing resumes/tokens; assess tenant exposure and reconcile uncertain provider actions; restore or repair under restricted access; repeat affected tests; rotate keys and reopen only reviewed features. If an external request already began before a pause, reconcile it rather than claiming that it was recalled.
